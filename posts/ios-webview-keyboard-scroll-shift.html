해결 ① ② · 코드

키보드 열림은 innerHeight − visualViewport.height > 150

iOS는 innerHeight가 그대로라 이 차이가 곧 키보드 높이. iPhone 소프트 키보드는 260pt 이상.

// ① onFocus
const isKeyboardShown = (vv) =>
  window.innerHeight - vv.height > 150

export function hideUntilKeyboardShown({ currentTarget: textarea }) {
  const vv = window.visualViewport
  if (!vv || !isIOS() || textarea.disabled) return
  if (isKeyboardShown(vv)) return  // 커서 이동 탭

  textarea.style.opacity = '0'
  const restore = () => { clearTimeout(timer)
    vv.removeEventListener('resize', onResize)
    textarea.style.opacity = '' }
  const onResize = () => { if (isKeyboardShown(vv)) restore() }
  const timer = setTimeout(restore, 1000)
  vv.addEventListener('resize', onResize)
}
// ② useEffect
let wasShown = isKeyboardShown(vv)
const onResize = () => {
  const shown = isKeyboardShown(vv)
  if (wasShown && !shown &&
      document.activeElement === textarea)
    textarea.blur()
  wasShown = shown
}
vv.addEventListener('resize', onResize)

체크리스트 · 다음에 비슷한 문제를 만나면

iOS 웹뷰 키보드 이슈 점검 순서

  • transform 보정보다 밀림 자체를 막을 수 있는지 먼저 본다
  • focus·resize·scroll 순서를 임시 로그로 찍어 타이밍 확인
  • 키보드 열림은 innerHeight − vv.height로 판정 (웹뷰가 줄어드는 환경에선 안 통함)
  • 네이티브가 키보드를 내리면 DOM 포커스도 푼다
  • 조상 transform은 필요할 때만. 안쪽 fixed 기준이 바뀐다
  • 검증은 새로고침이 아니라 앱 새 실행 후 여러 번
  • 같은 "헤더 튐"도 플랫폼마다 원인이 다르다 (iOS: WebKit 밀림 · Android: adjust=pan)
